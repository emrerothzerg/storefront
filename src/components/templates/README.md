# templates
Page-level layouts that arrange organisms into a structure without route-specific data (e.g. catalog layout, checkout layout). Routes in `src/app/` fill templates with data. Owner: programmer.

### StaticPage (T89)

Server-safe template for policy, company and help pages (`/about`, `/shipping`, `/returns`, `/privacy`, `/terms`, `/accessibility`, help topics). Renders an `<article>` labelled by its only `<h1>` (`#static-page-title`): `Breadcrumb` (hrefs failing `isAllowedInternalHref` render as plain text), the title, "Last updated <time>November 7, 2026</time>", an info `Notice` with `SAMPLE_POLICY_NOTICE`, intro paragraphs, an "On this page" `<nav>` inside a white `Card` (T171 light-only pass; only when there are MORE than 3 sections; links are same-document `#<section-id>` fragments), then `<section id>` blocks of `<h2>` + `<p>` text children at `max-w-prose`, then `children`; `aside` goes in a right column on `lg`, below on narrow screens. Everything is plain text: no HTML parsing.

| Props | |
| --- | --- |
| `title: string` | the page `<h1>` |
| `breadcrumb: readonly { label; href? }[]` | root to current page |
| `sections: readonly { id?; heading; paragraphs: readonly string[] }[]` | ids = slugified `id` or heading, unique (`-2`, `-3`), never `main`/`static-page-title` |
| `lastUpdated?: string` | ISO date; invalid -> line omitted |
| `sampleNotice?: boolean` | shows the Notice and skips the first paragraph of the first section when it equals `SAMPLE_POLICY_NOTICE` (policy content always starts with it) |
| `intro?: readonly string[]`, `aside?: ReactNode`, `children?: ReactNode`, `className?` | |

Policy page usage: `<StaticPage title={page.title} breadcrumb={[{ label: "Home", href: "/" }, { label: page.title }]} sections={page.sections} lastUpdated={page.lastUpdated} sampleNotice={page.sampleNotice} />`. Helpers: `slugifyHeading`, `buildSectionIds`, `formatLastUpdated`, `STATIC_PAGE_TOC_THRESHOLD` (3). If you pass a `FaqList` as `children`, its `<details id={slug}>` ids share the document with section ids; content slugs are question-shaped so they do not collide in practice.

### ListingTemplate (T91) + `src/app/_listing/parse-params.ts`

Server-safe template for `/search` (T105), `/category/[slug]` + `/brand/[slug]` (T106) and `/products`, `/deals`, `/best-sellers`, `/new-arrivals` (T107), `/top-rated` (CONS-B1). **v3 layout (T158, listing reference), single column, no left sidebar:** `Breadcrumb` (hrefs failing `isAllowedInternalHref` render as text) → the only `<h1>` (`#listing-title`) → result count `#listing-result-count` ("1–24 of 60 results", "33–48 of 48 results", "1 result", "0 results"; page beyond the last: "48 results"; promo tiles are never counted) → optional related-search `ChipRow` (`relatedSearches`, `nav` named "Related searches" with a visible non-heading label; omitted when none survive validation) → `children` slot → a results block: visually hidden `<h2>Results</h2>`, then ONE toolbar row = `FilterSidebar` v3 (the "Filter" pill `<details>` on the left with the applied-count badge; its panel `aside[aria-label="Filters"]` opens above the grid; `dealsCount = facets.deals`) with `toolbarEnd` = `SortSelect` GET form + `role="group" aria-label="View"` "Grid"/"List" pill **links** (`aria-current="true"` on the current one) on the right (below `md` the view group is `hidden md:flex` and the sort label is icon-only, so the row is Filter + compact Sort and never wraps at 320 px with JS; without JS the visible "Apply" button may wrap to a second line, no horizontal overflow; T179 U07); then `ProductGrid layout={params.view}` at full width (`promoSlots` forwarded with `page = params.page`, `pageSize = result.pageSize`, fallback `LISTING_TEMPLATE_PAGE_SIZE` 24), `Pagination` in `<nav aria-label="Listing pages">` (pill items, `rel="prev"`/`rel="next"` and hrefs `buildListingHref(base, params, { page })` unchanged, every filter kept) → optional `FeedbackBlock` after the results. The sort controls render only when `total > 0`; the Filter pill when `total > 0` or a filter is applied (override `showFilters`); with filters hidden but results present the row holds only sort + view. 0 results → `emptyState` or the default ("No results" + "Clear filters" = `base?q=` when that differs from the current URL). Page beyond the last → "This page is empty" + "Go to the last page" (no pager). Exactly two GET forms (sort + filters), never nested (plus one quick-add POST form per card when `addToCart` is passed). Headings: exactly one `h1`; the chips and the toolbar add none (the Filter panel heading is off: `FilterSidebar headingLevel` is not passed); outside cards only the sr-only "Results" `h2` and the feedback `h2` (cards `h3`, promo tiles `h3`).

| --- | --- |
| `title`, `breadcrumb: readonly { label; href? }[]` | plain text |
| `params: ListingParams` | from `parseListingParams(searchParams).params` — the SAME object used to build the service query |
| `facets: FacetCounts`, `result: { items, total, page, pageCount, pageSize }` | from ONE `listingService.list()` call (`ListingResult` fits `result` directly) |
| `base` | literal route path ("/search", `/category/${slug}`) |
| `labels: ActiveFilterLabels` | slug → name for chips |
| `sort?: ListingSort` | pass `result.sort` (else URL sort, then `defaultSort`, then `defaultSortFor(q)`) |
| `defaultSort?: ListingSort` | the ROUTE default sort (CONS-B1, D-T107-2): `best_selling` on /best-sellers, `newest` on /new-arrivals, `rating` on /top-rated; omit elsewhere (= `featured`, or `relevance` with `q`). Only this value is omitted from the template's links (pagination, view toggles, filter form + Reset, sort form, "Go to the last page"), so a user-chosen `featured` survives on those routes. Pass the same value the loader used (`CollectionPageView.defaultSort`); rel links/canonical follow the same rule. Not yet forwarded to `FacetGroup`/`PriceFacet`/`ActiveFilters` links (molecule owner request) |
| `showCategoryFacet?` (true), `showFilters?`, `sortOptions?`, `emptyState?`, `children?`, `cardProps?`, `headingLevel?: 1`, `className?` | `cardProps` has NO default (`ProductListItem.rank` is the search position, not a best-seller rank); `/best-sellers` passes `positionRankCardProps(result.page, result.pageSize)` |
| `relatedSearches?: readonly ChipRowItem[]`, `relatedSearchesLabel?` ("Related searches") | v3 chip row under the heading; the page builds the items (search: suggestions ≤ 12 without the current query; category: sibling categories, label "Related categories"; brand: other brands, label "More brands"). `{ query }` → `/search?q=…`, `{ label, href }` must pass the route allow-list |
| `promoSlots?: readonly ProductGridPromoSlot[]` | v3: `{ afterIndex, tile }` passed to `ProductGrid` (page 1 only, max 3, grid layout only, trailing tile only on a full page). The template never invents promos and drops them when a facet filter is applied (`hasActiveFilters`; `q` alone does not suppress); the page applies the rest of L-15 (threshold of 8 results, `dept` on search) |
| `feedback?: boolean \| { heading?; suggestions? }` | v3 `FeedbackBlock` after the results; absent/`false` = none, `true` = default heading + suggestions, object = the page's own 2–3 links. Shown only when `total > 0` or `q` is non-blank (`showListingFeedback`) |
| `addToCart?: CartActionFn`, `cardVariant?: ProductCardVariant` | v3 card extras for every card: `quickAdd: { action: addToCart }` ("+ Add", one unit, disabled when out of stock) and `variant`; `cardProps` is applied after them and wins |
| `now?: Date` | CLEANUP-P3 (ci): the page's single clock, forwarded as `ProductGrid now` so cards can show "New" (needs `publishedAt` on the item). Omitted = no "New" badge; nothing reads the clock. A `now` from `cardProps` still wins for that card, so `listingCardProps(now)` keeps working |

Parser (`parseListingParams(searchParams, { allowedBrands?, preserve? }) → { params, ignored: { key, value, reason }[] }`, never throws, `ignored` capped at 50, values shortened to 64):

| Key | Rule | Default |
| --- | --- | --- |
| `q` | first value; control chars → space, `\p{Cf}` + lone surrogates removed, whitespace collapsed, trimmed, ≤ 100 code units (no split pair; only the first 1000 are scanned) | none |
| `dept`, `category` | `^[a-z0-9-]{1,64}$` | none |
| `brand` | repeated; each slug-shaped (and in `allowedBrands` if given); deduped, sorted, max 10 | none |
| `min`, `max` | WHOLE DOLLARS (T63 convention), `^\d{1,9}$`, 0..1,000,000; `min > max` drops both | none |
| `rating` | `1`–`4` | none |
| `instock`, `deals` | only `"1"` | false |
| `sort` | `LISTING_SORTS` | `relevance` with `q`, else `featured` (omitted from URLs) |
| `page` | 1..1000 | 1 (omitted) |
| `view` | `grid` \| `list` | grid (omitted) |
| others | `p`, `ref`, `utm_source/medium/campaign/term/content` → `params.extra` (first value, ≤ 200 chars, cleaned); everything else dropped into `ignored` ("unknown parameter") | — |

Single-valued keys take the first string; the rest are reported "repeated"; non-strings "not a string"; empty strings "empty". Template helpers: `promoPaging(params.page, result.pageSize)`, `showListingFeedback(total, q)`, `LISTING_TEMPLATE_PAGE_SIZE` (24, mirrors `LISTING_PAGE_SIZE`; components do not import `src/app`), `LISTING_RELATED_LABEL`. Parser helpers: `buildListingUrl(base, params, patch?)` (= T63 `buildListingHref`: fixed key order, defaults omitted, extras last sorted; round trip is a fixed point, property-tested), `canonicalListingUrl(base, params)` (keeps `q` + `page`, strips facets/`dept`/sort/view/extras; a faceted or re-sorted URL canonicalises to the page-1 base — no listing helper exists in `src/lib/seo`, pass the result as `buildMetadata({ path })`), `isFacetedListing(params)` (→ `robots: noindex, follow`), `paginationRel(base, params, pageCount) → { prev?, next? }` (emit as `<link rel="prev|next" href={absoluteUrl(...)}/>`; React 19 hoists `<link>` into `<head>`), `toListingQuery(params, { categorySlug?, defaultSort?, pageSize?, ids?, dealsOnly?, now? })` (category = `params.category ?? categorySlug ?? params.dept`; `min*100`, `max*100+99`), `searchParamsToRecord`.

Page recipe: `const sp = await searchParams; const { params } = parseListingParams(sp); const r = getListingService().list(toListingQuery(params, {...})); <ListingTemplate params={params} facets={r.value.facets} result={r.value} sort={r.value.sort} … />`. In the app, routes use `src/app/_listing/listing-page.ts` instead (`parseRouteParams` + `loadListing`): `list()` returns `NOT_FOUND` for an unknown `category`/`dept` slug, so `loadListing` drops unknown URL slugs BEFORE the call (`dropUnknownCategorySlugs`, one `breadcrumb(slug)` lookup per present slug) and calls `list()` exactly once (D-T105-1; the old retry is gone). T106 404s only for the ROUTE slug.

Route rules in `listing-page.ts` (CONS-B1):

- `q` is a `/search`-only parameter (`ListingRouteConfig.allowQuery`, set only by /search): every other listing route drops `q` from params, links and canonical (canonical = page-1 base), and it never filters there (D-T107-1).
- Each route declares its default sort (`ListingRouteConfig.defaultSort` / `COLLECTIONS[kind].defaultSort`); `isFacetedForRoute`, `canonicalListingUrl`, `paginationRel`/`listingRelLinks` and the template's links all use it, so the sort kept in a URL is exactly the sort that marks a page re-sorted (noindex, follow).
- Facets rule (ruling D-T106-1, accepted): `facets` must come from the single `list()` call. A route may hide one dimension by passing a shallow copy with that one bucket emptied (the brand page passes `{ ...result.facets, brands: [] }`); every other bucket must be the very object `list()` returned.
- `/top-rated`: `COLLECTIONS["top-rated"]` (`defaultSort: "rating"`, indexable, canonical `/top-rated` or `/top-rated?page=N`, ItemList + BreadcrumbList JSON-LD). It sorts the whole published catalogue by average rating; the home rail's `topRated()` additionally requires a minimum review count.
- Meta descriptions are 70–160 characters (T112 audit): collection copy in `COLLECTIONS`; category/brand pages compose one with `composeMetaDescription(lead, contexts)` (`categoryDescription`, `brandDescription`).
- v3 page extras (T167), all in `listing-page.ts`: `listingPromoSlots({ base, params, total, promos? })` → up to 3 span-2 `PromoTile` slots from `src/content/listing-promos.ts` at `LISTING_PROMO_AFTER_INDEXES` `[1, 7, 13]` (grid `li` 3, 10, 17; an even cell count 2/10/18 before each tile at 4 columns, `promoCellsBefore`), only on page 1, `total >= LISTING_PROMO_MIN_RESULTS` (8), no facet or `dept`, skipping tiles whose CTA is the current route; `listingFeedback(base)` → 3 suggestion links (never the current route); `categoryChips(siblings)` / `brandChips(brandsWithCounts, currentSlug)` → `relatedSearches` (≤ 12; collections pass none; an empty category shows none because its empty state lists the siblings); `listingCardProps(now, inner?)` → `cardProps` that hand every card the loader's single `now` (since CLEANUP-P3 (ci) the template also accepts `now` and forwards it to `ProductGrid`; either works, `cardProps` wins; `/best-sellers` wraps `positionRankCardProps`). Views (`CollectionPageView`, `CategoryPageView`, `BrandPageView`) expose `now`, `promoSlots`, `feedback` (+ `relatedSearches` on category/brand). Pages pass `addToCart` (`@/app/actions/cart`) and `cardVariant="default"`.
