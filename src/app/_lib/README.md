# `src/app/_lib`: per-page logic helpers

Private folder (the leading `_` keeps it out of routing). Each file holds the data-loading and pure logic for one page, so the page component stays a thin renderer and the logic is unit-testable without Next.js. Helpers take their dependencies (repositories, services) as parameters with production defaults, do not catch repository errors (they surface to `error.tsx`), and never call `connection()` themselves; the page does that first. Add one file per page and note its owning task here.

The MVP `catalog.ts` (`loadCatalog()`, T21) was removed in the consistency pass (al): the home page has used `home.ts` since T96.

Root layout header data (T80) lives in `src/app/_layout/` rather than here, because it serves the layout and not a page. `header-data.ts` has `loadHeaderData(deps)`, tested in `header-data.test.ts`. It differs from the page helpers above in one way: the header must never take a page down, so database read errors are caught (with `unstable_rethrow` first) and replaced by fallbacks. See `src/app/_layout/README.md`.

Page shells (T171, Phase 3 light-only pass): account, orders, lists, help, FAQ, auth, 404 and error pages compose their own panels from the `Card` atom (white `raised` panels; `sunken` for empty states and secondary asides; `Card as="li"`/`as="section"` where the element was already an `li`/`section`) and pill links via `Link variant="button"` (`buttonVariant="outline"` for secondary actions). No route-local `_lib` loader changed; metadata, robots, canonicals, guest states and redirects are unchanged. The per-route `_lib` folders (`account/_lib`, `account/settings/_lib`, `lists/_lib`, `orders/_lib`, `help/_lib`, `faq/_lib`, `contact/_lib`, `compare/_lib`) stay next to their routes.
